# Tool Page v1

## Purpose

This mockup is the visual reference for the Tool Details page.

It demonstrates the overall layout, information hierarchy and visual style.

The implementation should follow this design while remaining responsive, accessible and component-driven.

The mockup is **not** intended to be reproduced pixel-perfect.

---

## Layout

The page consists of the following sections:

1. Breadcrumb navigation
2. Tool hero
3. Overview
4. Key features
5. Statistics
6. Newsletter
7. Footer

Each section should be implemented as an independent reusable component whenever possible.

---

## Tool Hero

The hero section contains:

- tool logo
- tool name
- verification badge
- short description
- rating
- review count
- categories/tags
- primary CTA
- secondary actions
- pricing summary
- supported platforms
- website link

This section should immediately communicate the most important information about the tool.

---

## Overview

The overview section contains:

- short product description
- list of key highlights

Keep the content concise and easy to scan.

---

## Key Features

Display the main capabilities of the product using reusable feature cards.

Each card should contain:

- icon
- feature title
- short description

Cards should have a consistent height and spacing.

---

## Statistics

Display several high-level facts about the product.

Examples include:

- users
- reviews
- founded year
- category

Statistics should be presented in a simple horizontal layout.

---

## Visual Style

Follow the ToolDB design system.

Important characteristics:

- generous whitespace
- clean typography
- rounded cards
- subtle borders
- minimal shadows
- restrained use of accent colors
- consistent spacing

---

## Responsiveness

The desktop layout should gracefully adapt to tablets and mobile devices.

Preserve the information hierarchy rather than the exact layout.

Cards may stack vertically on smaller screens.

---

## Implementation Guidelines

- Follow the project's design system.
- Use design tokens.
- Build reusable Vue components.
- Avoid hardcoded values.
- Keep components small and focused.
- Prefer maintainability over pixel-perfect implementation.

---

## Notes

This mockup represents the initial version of the Tool Details page.

The exact content and individual blocks may evolve as the project grows.
