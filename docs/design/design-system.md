## Purpose

This document defines the visual principles of ToolDB.

It complements the design mockups stored in this directory and explains how the interface should be implemented.

Visual references are design guidance, not pixel-perfect specifications.

---

# Design Philosophy

ToolDB should feel:

- modern
- minimal
- spacious
- professional
- trustworthy

The interface should help users discover and compare tools as quickly as possible without unnecessary visual distractions.

Clarity always takes priority over decoration.

---

# Design Characteristics

The visual identity of ToolDB is based on a few consistent principles:

- generous whitespace
- clean typography
- subtle borders
- soft rounded corners
- minimal shadows
- restrained use of accent colors
- consistent spacing
- predictable layouts

The interface should feel calm, lightweight and easy to scan.

---

# Layout

## Containers

- Keep content centered.
- Use a consistent maximum content width.
- Maintain generous horizontal spacing.
- Keep section spacing consistent across the application.

## Sections

Each section should have a clear purpose.

Avoid visually merging unrelated content.

Prefer whitespace instead of additional separators.

---

# Cards

Cards are the primary building block of the interface.

Every card should have:

- consistent border radius
- subtle border
- comfortable padding
- clean typography
- minimal or no shadow

Cards should rely on spacing and hierarchy rather than visual effects.

---

# Colors

The interface should primarily use neutral colors.

Accent colors should only emphasize:

- primary actions
- active navigation
- selected elements
- important links
- ratings
- small visual highlights

Accent colors should never dominate the page.

---

# Typography

Typography creates the visual hierarchy.

Guidelines:

- large page titles
- clear section headings
- comfortable body text
- high contrast
- consistent heading scale

Prefer typography over decorative effects.

---

# Buttons

Buttons should communicate importance clearly.

Guidelines:

- one primary action per section
- secondary actions should remain visually lightweight
- consistent sizing
- consistent border radius

Avoid unnecessary button styles.

---

# Inputs

Inputs should feel simple and unobtrusive.

Guidelines:

- subtle borders
- generous padding
- clear focus states
- minimal decoration

---

# Icons

Use Lucide icons consistently.

Icons should:

- support understanding
- remain visually lightweight
- use consistent sizing
- never replace meaningful text

---

# Navigation

Navigation should feel lightweight and predictable.

Prefer:

- simple labels
- generous spacing
- clear active states
- minimal visual noise

---

# Lists and Grids

Lists should be easy to scan.

Prioritize:

- consistent alignment
- equal card heights where appropriate
- balanced spacing
- predictable layouts

Avoid irregular grids.

---

# Whitespace

Whitespace is an essential part of the design.

Prefer adding space instead of:

- borders
- separators
- background colors
- decorative elements

The interface should never feel crowded.

---

# Responsiveness

Design mobile-first.

When adapting layouts:

- preserve hierarchy
- preserve spacing proportions
- avoid horizontal scrolling
- stack sections naturally

Readability is more important than fitting more content on screen.

---

# Accessibility

Accessibility is mandatory.

Always provide:

- semantic HTML
- keyboard navigation
- visible focus states
- sufficient color contrast
- accessible labels
- responsive layouts

Accessibility always takes precedence over visual perfection.

---

# Implementation Guidelines

When implementing UI:

- Follow the visual references in this directory.
- Use the project's design tokens.
- Reuse existing components whenever possible.
- Avoid hardcoded values.
- Maintain visual consistency across all pages.
- Build reusable rather than page-specific solutions.

Technical quality, maintainability and consistency always take priority over pixel-perfect implementation.
